# שלב ב': יצירת בקרה בשפה חופשית (הדגמה עם Mock)

## מה נבנה

| דרישת המטלה | איפה זה במערכת |
|---|---|
| ממשק להזנת תיאור בשפה חופשית | המסך "יצירה בשפה חופשית" (`/ai`), עם דוגמאות מוכנות ללחיצה |
| מנגנון להעברת מבנה הנתונים ומשמעותם העסקית למודל | `AiSchemaContextBuilder` ב־.NET בונה "הקשר" מתוך `meta`: ישויות, שדות, סוגים, יחידות, מילים נרדפות, ערכים אפשריים ונתיבי קשר. **בלי שמות טבלאות או עמודות.** אפשר לראות אותו ב־`GET /api/ai/schema-context` |
| הגדרת מבנה התשובה המצופה | החוזה `ControlSuggestion` ב־[`ai-service/app/schemas.py`](../ai-service/app/schemas.py): הגדרת בקרה (אותו חוזה של שלב א'), שם, חומרה, הסבר, רמת ביטחון ואזהרות |
| קליטת תשובת AI באמצעות Mock | `MockProvider`: מפענח עברית מבוסס כללים, שעובד רק לפי ההקשר שהתקבל |
| תרגום התשובה להגדרת בקרה של שלב א' | התשובה **היא** הגדרת בקרה של שלב א'. ה־.NET מאמת אותה באותו `ControlDefinitionValidator` ומתאר אותה באותו `DefinitionDescriber` |
| הצגה לאישור לפני הרצה | המסך מציג תיאור במילים, תקינות, הסבר ואזהרות. אפשר **לאשר ולשמור**, **לערוך בעורך** או **להריץ ניסיון**. בלי אישור, שום דבר לא נשמר ולא רץ |
| הפרדה בין ה־AI למנגנון הבקרות | שירות Python נפרד, עם ממשק `AiProvider`. החלפת מודל נעשית בשינוי `AI_PROVIDER`, בלי שינוי בלוגיקת הבקרות |
| משימת רשות: הצעות יזומות | `quality_advisor.py` מנתח את **מבנה** הנתונים ומציע בקרות איכות. מוצג באותו מסך |

## הדגמה בממשק

1. מריצים את שלושת התהליכים (ראו [README](../README.md)) ונכנסים ל"יצירה בשפה חופשית".
2. לוחצים על הדוגמה: "מצא עובדים פעילים שגילם נמוך מ־18 ומשכורתם גבוהה מ־15,000 ש"ח".
3. מוצגת הצעה:
   - **תיאור:** עובדים – עובד פעיל: כן וגם גיל קטן מ־18 שנים וגם שכר חודשי גדול מ־15,000 ש"ח
   - **איך הובן כל חלק:** "שגילם" ← גיל: קטן מ־18, ‏"ומשכורתם" ← שכר חודשי: גדול מ־15000
   - **ביטחון:** 92%
4. לוחצים על "הרצת ניסיון", והתוצאה היא עובד אחד: אלון חדד, בן 16 עם שכר של 17,000 ש"ח. ליאור אזולאי עומד גם הוא בתנאי הגיל והשכר, אבל אינו פעיל.
5. לוחצים על "אישור ושמירה". הבקרה נשמרת עם `source = ai` ומופיעה ברשימת הבקרות.

## הדגמה דרך ה־API

<div dir="ltr">

```http
POST http://localhost:5080/api/ai/suggest-control
Content-Type: application/json

{ "text": "מצא עובדים פעילים שגילם נמוך מ־18 ומשכורתם גבוהה מ־15,000 ש\"ח" }
```

</div>

תשובה (מקוצרת):

<div dir="ltr">

```json
{
  "name": "עובדים פעילים שגילם נמוך מ־18 ומשכורתם גבוהה מ־15,000 ש\"ח",
  "severity": "medium",
  "definition": {
    "version": 1,
    "entity": "Employee",
    "condition": {
      "type": "group", "logic": "and", "negate": false,
      "conditions": [
        { "type": "rule", "field": "isActive", "operator": "isTrue" },
        { "type": "rule", "field": "age",      "operator": "lessThan",    "value": 18 },
        { "type": "rule", "field": "salary",   "operator": "greaterThan", "value": 15000 }
      ]
    }
  },
  "definitionText": "עובדים – עובד פעיל: כן וגם גיל קטן מ־18 שנים וגם שכר חודשי גדול מ־15,000 ש\"ח",
  "isValid": true,
  "errors": [],
  "explanation": [
    "נתונים: עובדים (זוהה מהמילה \"עובדים\")",
    "\"עובדים פעילים\" ← עובד פעיל: כן",
    "\"שגילם\" ← גיל: קטן מ־18",
    "\"ומשכורתם\" ← שכר חודשי: גדול מ־15000"
  ],
  "confidence": 0.92,
  "warnings": [],
  "provider": "mock",
  "model": "rule-based-hebrew-v1"
}
```

</div>

השדות `definitionText`, `isValid` ו־`errors` מתווספים ב־.NET, אחרי אימות ההצעה. שירות ה־AI לא קובע בעצמו אם ההצעה תקינה.

## מקרים מיוחדים

| קלט | מה קורה |
|---|---|
| "עובדים פעילים במחלקה שאינה פעילה" | המילה "פעילה" יכולה להתאים גם לשדה של העובד וגם לשדה של המחלקה. ה־Mock בוחר לפי הישות שהוזכרה אחרונה לפני המילה ("מחלקה"), ולכן ההגדרה היא `department.isActive = לא` |
| "פרויקטים שתקציבם שלילי או שתאריך הסיום מוקדם מתאריך ההתחלה" | קבוצת "או", ובה השוואה בין שני שדות תאריך |
| "עובדים שגילם נמוך מ־18 ושהם נולדו ביום שלישי" | התנאי על הגיל נכנס להגדרה. החלק "ושהם נולדו ביום שלישי" **לא מנוחש**: הוא מוצג כאזהרה, ורמת הביטחון יורדת |
| "מה מזג האוויר מחר?" | תשובת 422 עם הודעה בעברית: לא זוהו נתונים שעליהם תרוץ הבקרה |
| שירות ה־AI כבוי | תשובת 503: "שירות ה־AI אינו זמין". שאר המערכת ממשיכה לעבוד כרגיל |

## הצעות יזומות לבקרות איכות (משימת רשות)

`POST /api/ai/quality-suggestions` מנתח את מבנה הנתונים בלבד, לפי כללים כלליים שלא תלויים בטבלה מסוימת:

| כלל | דוגמה להצעה שנוצרת |
|---|---|
| זוג שדות תאריך של התחלה וסיום | עובדים: תאריך סיום העסקה לפני תאריך תחילת העסקה |
| שדה כספי | פרויקטים: תקציב הפרויקט שלילי |
| שדה "פעיל" ברשומה וגם ברשומה המקושרת | חוסר עקביות: עובד פעיל אך לא מחלקה פעילה |
| רשומה פעילה עם תאריך סיום | חוסר עקביות: עובד פעיל אך תאריך סיום העסקה עבר |
| שדות זיהוי וקשר | עובד פעיל עם פרטי זיהוי או קשר חסרים |

על נתוני הדוגמה נוצרות 9 הצעות, וכולן עוברות את האימות של ה־.NET. כל הצעה אפשר לאשר, לערוך או להריץ, בדיוק כמו הצעה מטקסט חופשי.

## מעבר למודל אמיתי

שירות ה־Python כולל גם `ClaudeProvider` ([`claude_provider.py`](../ai-service/app/providers/claude_provider.py)):
- הוא משתמש ב־**Structured Outputs**, כך שהמודל מחויב להחזיר JSON בדיוק לפי סכמת `ControlSuggestion`.
- ההוראות למודל נבנות ב־[`prompt_builder.py`](../ai-service/app/prompt_builder.py) מתוך אותו הקשר שה־Mock מקבל. אפשר לראות אותן ב־`POST /v1/prompt-preview` בשירות ה־Python.

הפעלה (לא נדרשת ולא בוצעה במסגרת המטלה):

<div dir="ltr">

```powershell
$env:AI_PROVIDER = "claude"
$env:ANTHROPIC_API_KEY = "<מפתח>"
.venv\Scripts\python -m uvicorn app.main:app --port 8000
```

</div>

ה־.NET, ה־Angular ולוגיקת הבקרות לא משתנים בכלל. זו ההוכחה שההפרדה אמיתית.
